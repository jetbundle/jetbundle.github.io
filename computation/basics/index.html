basics of computation

formal yet physics first. computation is the controlled evolution of physical information bearing states under fixed operators acting on finite memory geometries.

i formalize computation the way a physicist builds mechanics: start from objects that exist on the bench (machines, memory, distinguishable states), then derive syntax, not the reverse. this page is a deliberately critical reordering of how the subject is usually taught, written to be read as a single treatise rather than a tutorial index.

the strongest claim here is not that computer science is wrong. many criticisms of the field itself are unfair. what is often justified is criticism of the educational decomposition: syntax before ontology, languages mistaken for the subject itself, memory hidden until late, state buried inside objects, hardware treated as optional, performance framed as a late optimization pass, numerical methods isolated from programming, parallelism deferred as advanced, scientific computing fragmented into unrelated silos. that stack is historically contingent, not conceptually necessary. mature practitioners reason from the tuple \((\text{State}, \text{Operator}, \text{Memory}, \text{Evolution})\). everything else, including C, Rust, CUDA, climate models, and geometry engines, is a projection of the same structure.

the risk is philosophy without contact. every section below states definitions in plain language, introduces the symbols before using them, and pairs the prose with at least one interactive demonstration you can run on this page: mathematical object, physical realization, machine representation, and evolution you can watch.

I · machines

the starting point is not software. before one writes for(int i=0;i<n;i++) one must ask what a computer actually is. a physicist would not memorize \(F=ma\) before mass, force, and acceleration are understood as objects in the world. programming is often taught in the opposite order: symbols first, ontology later. this section repairs that order.

definition · finite dynamical system

Definition. A computing machine is a finite physical system characterized by two data:

  • a state set \(\mathcal{S}\), the collection of all microscopically distinguishable configurations the hardware can occupy;
  • a transition map \(F:\mathcal{S}\to\mathcal{S}\), the rule that advances the machine from one configuration to the next when a clock cycle completes.

At discrete times \(t = 0,1,2,\ldots\), the microstate \(S_t \in \mathcal{S}\) evolves according to

\[ S_{t+1} = F(S_t). \]

Here \(S_t\) is not an abstract variable. It encodes register contents, RAM cell voltages, cache tags, and whatever other physical degrees of freedom the architecture exposes. The cardinality \(W = |\mathcal{S}|\) is enormous but finite: a real machine has no access to continuous state space.

A program, in this view, is not primarily a text file. It is a specification of the map \(F\) together with initial data \(S_0\). Source code is a human readable encoding of that specification; the executing process is the trajectory \(S_0, S_1, S_2, \ldots\) on the hardware.

the transition operator as the unit of execution

Modern CPUs implement \(F\) as a pipeline: fetch an instruction from memory, decode it, execute it, write results back to memory, then repeat. Each full pass is one application of \(F\). Cellular automata, molecular dynamics timesteps, finite difference stencils, and forward passes through neural networks are the same mathematical pattern at different scales: a state vector updated by a fixed rule.

elementary cellular automaton as a visible model

Rule 110 is a one dimensional cellular automaton. Label cells by \(i \in \mathbb{Z}/N\mathbb{Z}\) on a ring of length \(N\). Each cell holds a bit \(s_i \in \{0,1\}\). The global state is \(S_t = (s_0,\ldots,s_{N-1})\). A local rule \(R:\{0,1\}^3\to\{0,1\}\) reads the neighborhood \((s_{i-1},s_i,s_{i+1})\) and writes the next bit:

\[ s_i' = R(s_{i-1}, s_i, s_{i+1}). \]

All cells update in parallel, producing \(S_{t+1} = F(S_t)\). Press next step below: you are watching the same state update pattern a CPU performs, only on a grid you can see.

II · information

before arrays, loops, or syntax: what is information? In physics it is not a file size and not a database column. Information is distinguishability between physical states. If two microstates can be reliably told apart by measurement, they carry different information. If they cannot, they are the same information for all operational purposes.

definition · shannon entropy

Definition. Suppose a system can occupy \(W\) microstates, all equally likely. The information required to specify which one it occupies is

\[ H = \log_2 W \quad \text{(bits)}. \]

When microstates are not equally likely, assign probabilities \(p_i\) with \(\sum_i p_i = 1\). The Shannon entropy is

\[ H = -\sum_i p_i \log_2 p_i. \]

This quantity measures average uncertainty before measurement. It satisfies \(0 \leq H \leq \log_2 W\), with equality on the upper bound only when every state is equally probable.

Memory stores information by pinning the machine into one of finitely many configurations. Computation transforms information by applying \(F\). Communication transports information by copying correlated physical degrees of freedom across space.

compression and redundancy

A highly repetitive string such as AAAAAAAAAAAAAAAAAAAA has low entropy per character because the next symbol is predictable. A pseudorandom hex string has entropy near the per character maximum for its alphabet. Compression is the removal of redundancy: finding a shorter description of the same distinguishable content. Kolmogorov complexity formalizes the shortest program that generates a string; Shannon entropy lower bounds the expected code length for independent draws from a source.

landauer's principle

Information is physical. Erasing a bit means merging two previously distinguishable microstates into one. That reduction of distinguishability cannot be free. Landauer's principle states that erasing \(N\) bits at temperature \(T\) dissipates at least

\[ E_{\mathrm{erase}} \geq N\, k_B T \ln 2 \]

joules of heat into the environment, where \(k_B\) is Boltzmann's constant. Reversible computation can avoid erasure in principle; real machines pay this thermodynamic cost whenever they overwrite memory without retaining the old value elsewhere.

III · memory

memory is the section where computation usually becomes concrete. Most introductory courses hide memory behind interpreters and garbage collectors. Yet every algorithm executes on memory: the CPU reads operands from addresses, performs arithmetic, and writes results back. High performance computing begins with the question of where bytes live and how they move.

definition · address map

Definition. Memory is a stable, addressable map

\[ M : \mathcal{A} \to \mathcal{V} \]

from an address space \(\mathcal{A}\) (typically a finite set of integers) to a value space \(\mathcal{V}\) (for example the 256 possible byte values). RAM is a physical device that realizes such a map: each address names a cell; each cell holds a voltage pattern interpreted as a value.

A pointer is a value \(p \in \mathcal{V}\) that is interpreted as an address. The C expression *p means: evaluate \(M(p)\) for a read, or update \(M(p)\leftarrow v\) for a write. There is no magic indirection layer in the physics; there is only a number stored in one cell that names another cell.

mutating state through pointers

int x = 5;        // write 5 into the cell named &x
int *p = &x;      // store the address of x into the cell named p
*p = 10;          // write 10 into the cell whose address is stored in p

After the final line, the variable name x is not required for the update to occur. The machine changed a physical degree of freedom at the address held in p. Use the explorer below to watch addresses, values, and interpretations change step by step.

memory hierarchy as a physical constraint

Not all addresses are equally fast to reach. Registers sit inside the processor core. L1 and L3 caches are small, fast SRAM banks. DRAM is large and slower. Storage is larger still and slower again. Each level trades latency \(\ell\) (time to first byte) against bandwidth \(B_w\) (bytes per second sustained). A useful lower bound on runtime is

\[ t \geq \max\!\left(\frac{\mathrm{FLOPs}}{P_{\mathrm{flop}}},\; \frac{\mathrm{bytes moved}}{B_w}\right), \]

where \(P_{\mathrm{flop}}\) is peak floating point throughput. When the second term dominates, the program is memory bound: rearranging what you fetch matters more than shaving arithmetic.

IV · state spaces

students often meet functions and classes before they meet state as a geometric object. Yet a molecular dynamics simulation has state (positions and velocities of every atom). A compiler has state (symbol tables and intermediate representations). A neural network at inference has state (activations in each layer). Viewing all of these as points in a configuration space makes the common structure visible.

definition · configuration vector

Definition. A state is a point in a configuration space \(\mathcal{X}\), written as a coordinate vector

\[ \mathbf{x} = (x_1, x_2, \ldots, x_n) \in \mathcal{X}. \]

The integer \(n\) is the number of scalar degrees of freedom in the model. The full microstate of a modern machine has \(n\) on the order of billions when every bit of RAM and every register is counted. A scientific program does not manipulate all coordinates at once; it chooses a chart: a subset of coordinates that represent the modeled phenomenon.

examples across physics and software

A free particle in three dimensions has \(\mathbf{x} = (\mathbf{r}, \mathbf{v}) \in \mathbb{R}^6\). A rigid body adds orientation \(R \in SO(3)\) and angular velocity \(\boldsymbol{\omega}\). A field discretized on a grid replaces continuous \(u(x,y,z)\) with values \(u_{i,j,k}\) at mesh points. A control program for a robot tracks joint angles and velocities. In every case, evolution is a trajectory \(\mathbf{x}(t)\) or a discrete sequence \(\mathbf{x}_0,\mathbf{x}_1,\ldots\).

phase space of a damped oscillator

Consider the second order equation \(\ddot{x} + 2\gamma \dot{x} + \omega^2 x = 0\), written as a first order system in \((x,v)\) with \(v=\dot{x}\):

\[ \dot{x} = v, \qquad \dot{v} = -\omega^2 x - 2\gamma v. \]

Here \(\omega\) is the natural frequency and \(\gamma\) is a damping coefficient. The pair \((x,v)\) is a point in phase space. The plot below integrates this system explicitly and draws the trajectory. State is not a metaphor here; it is a curve you can see.

V · operators

once a state space \(\mathcal{X}\) is fixed, dynamics require maps that carry one state to another. This is the central abstraction of computational science. A function call that updates memory, a compiler pass that rewrites an intermediate representation, and a numerical timestep are all instances of the same idea.

definition · operator on state space

Definition. An operator is a map

\[ \mathcal{O} : \mathcal{X} \to \mathcal{X}. \]

Given current state \(\mathbf{x}_n\), one application produces \(\mathbf{x}_{n+1} = \mathcal{O}(\mathbf{x}_n)\). If the map depends on parameters (time step, mesh spacing), write \(\mathcal{O}_{\Delta t}\) to make the dependence explicit.

iteration and the meaning of loops

Repeated application defines

\[ \mathcal{O}^n = \underbrace{\mathcal{O} \circ \mathcal{O} \circ \cdots \circ \mathcal{O}}_{n\ \text{times}}, \qquad \mathbf{x}_n = \mathcal{O}^n(\mathbf{x}_0). \]

A for loop in code is not merely syntactic convenience. It is the construction of \(\mathcal{O}^n\) by repeated evaluation. Stability, convergence, periodicity, and chaos are properties of the operator and its discretization, exactly as in classical mechanics.

the logistic map as a nonlinear example

The logistic map on the unit interval is

\[ x_{n+1} = r\, x_n (1 - x_n), \]

with parameter \(r\). For \(r \approx 3.9\) the orbit is chaotic: two nearby initial conditions diverge rapidly even though the formula is deterministic. Press apply below to iterate the map and watch sensitivity to initial data emerge from a single line of arithmetic.

VI · evolution

numerical analysis and programming are not separate subjects for the working scientist. Both approximate the same object: continuous evolution \(\dot{\mathbf{x}} = f(\mathbf{x})\) by discrete updates compatible with finite memory and finite timestep.

definition · discrete evolution scheme

Definition. A discrete evolution scheme is an operator \(T_{\Delta t}\) such that

\[ \mathbf{x}_{n+1} = T_{\Delta t}(\mathbf{x}_n) \approx \mathbf{x}(t_n + \Delta t) \]

for a continuous trajectory solving \(\dot{\mathbf{x}} = f(\mathbf{x})\). The error of the scheme depends on \(\Delta t\) and on the smoothness of \(f\).

explicit euler method

The simplest explicit scheme for \(\dot{x} = f(x)\) is Euler's method:

\[ x_{n+1} = x_n + \Delta t\, f(x_n). \]

In C this is literally x += dt * f(x);. The mathematics, the program, and the memory write to the cell holding x are the same action viewed in three languages.

stability as a property of the operator

Test the decay equation \(\dot{y} = -\lambda y\) with \(\lambda > 0\). Euler gives \(y_{n+1} = (1 - \lambda\Delta t)\, y_n\). The fixed point \(y=0\) is stable only if \(|1 - \lambda\Delta t| < 1\). Increase \(\Delta t\) in the demo below: when the inequality fails, the discrete orbit diverges even though the exact solution decays smoothly. That failure is not a bug in the compiler; it is the timestep violating the stability region of the scheme.

verlet integration for hamiltonian structure

For second order systems \(\ddot{x} = a(x)\), the velocity Verlet scheme reads

\[ x_{n+1} = x_n + v_n \Delta t + \tfrac{1}{2} a_n \Delta t^2, \] \[ v_{n+1} = v_n + \tfrac{1}{2}(a_n + a_{n+1})\Delta t. \]

Verlet is symplectic for Hamiltonian problems: it approximately preserves phase space volume and energy over long times, whereas Euler typically does not. Toggle integrators in the second demo to compare qualitative long time behavior on harmonic motion.

VII · memory geometry

on modern hardware, moving information often costs more than transforming it.

Two programs that perform the same floating point operation count can differ in wall clock time by large factors. The difference is not in the arithmetic; it is in memory geometry: how logical data structures are embedded into physical addresses, and therefore which cache lines and DRAM pages are touched when the operator runs.

definition · layout embedding

Definition. Let \(\mathcal{L}\) be a logical data structure (an array of particles, a sparse matrix, a tree). A layout embedding is an injective map

\[ \iota : \mathcal{L} \hookrightarrow \mathcal{A}^m \]

that places each logical element at a physical address in \(\mathcal{A}\). The geometry of \(\iota\) determines spatial and temporal locality when an operator scans the structure.

cache lines and locality

CPUs do not fetch individual bytes from DRAM. They fetch cache lines, typically 64 contiguous bytes. If your operator reads \(x_i\) and \(x_{i+1}\) lies in the same line, the second read is cheap. Spatial locality means nearby indices map to nearby addresses. Temporal locality means the same line is reused before eviction.

array of structures versus structure of arrays

In array of structures (AoS), each particle stores \((x_i,y_i,z_i)\) contiguously:

struct Particle { float x, y, z; } p[N];

In structure of arrays (SoA), coordinates of the same type are contiguous:

float x[N], y[N], z[N];

Summing all \(x_i\) touches every particle in AoS but strides across unrelated \(y_i,z_i\) fields, loading cache lines that are only partly used. SoA loads lines packed with useful \(x_i\) values. The operation count is identical; the bytes moved are not.

roofline bound

\[ t \geq \max\!\left(\frac{\mathrm{FLOPs}}{P_{\mathrm{flop}}},\; \frac{\mathrm{bytes}}{B_w}\right) \]

\(P_{\mathrm{flop}}\) is peak arithmetic throughput. \(B_w\) is memory bandwidth. when the byte term dominates, rearranging data layout matters more than shaving operations.

VIII · parallelism

parallelism is no longer an exotic topic reserved for supercomputers. A laptop CPU contains multiple cores with SIMD units; many machines also include a GPU. Teaching computation as purely sequential does not match the hardware students actually own.

definition · concurrent operators on subspaces

Definition. Parallel computation applies operators \(\mathcal{O}_i\) simultaneously on subspaces \(\mathcal{X}_i \subset \mathcal{X}\), with synchronization wherever two subspaces overlap (shared memory, halos in grid codes, locks on aliased data). The global evolution is coherent only if these interfaces are handled consistently.

amdahl's law

Suppose a fraction \(p\) of work parallelizes perfectly across \(N\) cores, and the remaining fraction \(1-p\) must run serially. Amdahl's law gives speedup

\[ S(N) = \frac{1}{(1-p) + p/N}. \]

As \(N \to \infty\), speedup approaches \(1/(1-p)\). A tiny serial section caps scalability no matter how many cores you buy. The slider below plots \(S(N)\) as a function of core count for your chosen \(p\).

communication as a time floor

Moving \(B\) bytes between cores or between host and device requires time at least \(t_{\mathrm{comm}} \geq B/B_w\), where \(B_w\) is link bandwidth. Total time satisfies

\[ t_{\mathrm{total}} \geq t_{\mathrm{comp}} + t_{\mathrm{comm}}. \]

Good parallel algorithms minimize \(B\) by keeping data local. False sharing occurs when two cores write different variables that happen to live in the same cache line, forcing expensive coherence traffic even though the logical variables are unrelated.

IX · representations

programming languages are often mistaken for the subject of computer science itself. They are not. They are representations: coordinate charts that map human readable syntax onto the same underlying machine objects (state, operator, memory layout).

definition · representation map

Definition. A programming language is a representation map

\[ \rho : \text{syntax} \to (\text{State},\ \text{Operator},\ \text{Memory geometry}) \]

that assigns program text to sequences of machine operations and data layouts. Changing \(\rho\) (switching from C to Python to Rust) does not change the physics of the silicon. It changes which aspects are visible, which are checked at compile time, and which are deferred to runtime.

the same euler step in five charts

Consider explicit Euler for \(\dot{x} = -\lambda x\):

\[ x_{n+1} = x_n + \Delta t\,(-\lambda x_n). \]

The update is the same operator in every language below. C exposes the memory address of x. Rust tracks ownership of the binding. Python hides addresses but still executes loads and stores on the interpreter's representation of x. Toggle the tabs and read the identical numerical kernel through different coordinate systems.

X · scientific architectures

computational fluid dynamics, finite element analysis, molecular dynamics, climate modeling, and quantitative finance are often taught as unrelated courses with unrelated software stacks. Practitioners frequently discover that the same architectural spine appears in each domain.

the four question template

Every serious system can be interrogated with four questions:

  1. What is the mathematical object being evolved?
  2. What is its physical realization in the laboratory or the world?
  3. What is the machine representation (arrays, sparse matrices, feature buffers)?
  4. What operator advances the state by one timestep or iteration?

closing

conventional curricula often begin with syntax: variables, loops, objects, frameworks. a physics first view begins earlier, with the machine as a finite dynamical system, information as distinguishability, memory as an address map, and programs as operators that evolve state under physical constraints.

that ordering is not nostalgia for assembly language. it is the decomposition mature computational scientists use when debugging performance, stability, and correctness at scale. languages enter late because they are charts on a fixed object, not the object itself.
